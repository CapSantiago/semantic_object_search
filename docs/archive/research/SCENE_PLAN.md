# 场景优化计划

本页是场景子计划；总顺序与阶段门槛以 [DEPLOYMENT_PLAN.md](../../maintained/DEPLOYMENT_PLAN.md) 为准。目标兼容集见 [TARGET_CATALOG.md](../../maintained/TARGET_CATALOG.md)，提前下载/部署状态见 [RESOURCE_PREPARATION.md](../../maintained/RESOURCE_PREPARATION.md)。先补当前配置下的任务书功能和语音/人工完整验收，后做导航比较与视觉探索。

当前状态：AWS 家庭场景已完成本轮真实传感器、建图、导航、厨房椅子任务三/四文本验收：单物体找到 1 把，完整统计为 4 把。部署、结果与运行指令见 [AWS_HOUSE.md](../../maintained/AWS_HOUSE.md)。原场景和 `maps/course_house.yaml` 保留为已验证的基础场景，入口为 `scene:=baseline`。下文的更多类别、语音和重复实验仍为后续计划。

现成场景调研见 [SCENE_RESEARCH.md](SCENE_RESEARCH.md)。已采用 AWS Small House 的房屋布置和独立家具，适配当前 Fortress；后续再补充课程任务物品。Lake House 作为住宅整体展示的备选，尚未接入。

原基础测试世界面积约 8×6 m，包含厨房、客厅、卧室，只有四把相同椅子：厨房两把，客厅和卧室各一把。现已独立保留。新增 AWS 场景约 19×11 m，摆放 87 个实例，含 8 把椅子；本轮完成厨房四把椅子的验证，其余类别与布局实验见后续计划。

## 开发顺序

1. 修复桌面启动：解决 Snap VS Code 注入 GTK/GIO 运行库的问题，提供 RViz 的地图、雷达、目标编号和 RGB 显示预设。
2. 增加独立的家具场景及对应地图，回归任务三、四。
3. 先补全房扫描覆盖、桌面高度目标、更多类别和失败/遮挡场景，完善任务/结果接口及自动实验。
4. 核心功能稳定后，接现成语音识别与规则任务解析，完成任务三、四人工端到端验收 G0；按总计划继续完成任务一语音建图/G1、任务二清扫返航及集成验收/G2。导航比较、视觉模型探索和可选大语言模型在 G2 后进行，GPU 按实际需求评估。场景定义提前共用房间多边形、入口、初始/充电位姿和禁行区域，清扫地面覆盖与相机观察覆盖分别验收。

## 第一阶段：房间和陈设

在已采用的约 19×11 m AWS 住宅中细化相机、房间边界和任务物品布置，保留厨房、客厅、卧室命名；主线先不另换房屋布局。

| 区域 | 计划陈设 | 搜索时要覆盖的位置 |
|---|---|---|
| 厨房 | 橱柜、灶台、冰箱、餐桌与餐椅 | 餐桌四周、柜前、桌面 |
| 客厅 | 沙发、茶几、电视柜、书架、座椅 | 茶几周围、沙发两侧、书架旁 |
| 卧室 | 床、衣柜、床头柜、书桌与椅子 | 床侧、书桌旁、柜前 |

加入有区分的地面/墙面材质、合理照明和门框。家具要有匹配的碰撞体和实际尺度，不能仅添加看起来像家具的贴图。主要通道与门洞按机器人尺寸留足转弯空间，初步门洞净宽至少 1.0 m，再以 Nav2 通行验证为准。

优先复用来源明确、允许项目使用的真实网格资产，记录作者、许可证、版本、修改和下载校验值。资源准备好后本地加载，避免演示时联网下载。

## 第二阶段：目标数量和任务变化

初步目标是约 20 个可搜索实例：8 把椅子、6 个瓶子、6 个杯子，分布在三个房间。数字是场景设计目标，尚未完成资产选择和识别验证。程序现有关键词解析已支持 chair、bottle、cup，但目前实测通过的类别只有 chair。

增加同类不同外观和非目标干扰物，并提供受控测试布局：

- 同一目标在多个视角重复出现，检查编号稳定、数量不增加。
- 相近的两个同类实例，检查是否误合并。
- 目标被桌腿、沙发或其他目标部分遮挡，多视点应补充可见区域。
- 相邻房间能通过门洞互相看见，检查是否只统计指定房间。
- 指定房间没有目标，检查返回 0/未找到，并与传感器或 TF 故障区分。

每个布局记录独立的场景真值，用于评估数量和位置。真值不能输入检测、目标关联或搜索决策链路。

杯子和瓶子放到桌面后，需要验证相机能看见桌面及物体。基础场景相机高度 0.30 m，AWS 场景为 0.65 m，均不能直接假定适合所有桌面搜索；将根据实际桌面高度和视野调整安装高度/俯仰，并同步更新 SDF、TF、碰撞外形和标定验证。

## 第三阶段：地图、观察点和验收

已提供基础场景 `scene:=baseline` 和家庭场景 `scene:=aws_house` 两个入口，各自对应地图、房间配置和测试结果；不能把原基础地图直接用于家庭场景。后续新增瓶子、杯子及重复实验仍需单独验收。

每次改变墙体、家具或机器人传感器后，按以下顺序复验：

1. Gazebo 碰撞、底盘运动、雷达、RGB-D、相机内参和 TF。
2. 从真实雷达重新建图，校正房间边界，验证每个门洞的导航通行。
3. 从实际 RGB 画面校正观察点，分别验证 chair、bottle、cup。
4. 在同一布局下比较单点与多点搜索，记录漏检、重复计数、位置误差、任务耗时。
5. 每个选定任务至少重复运行 5 次，记录场景真值、结果和逐帧关联；观察仿真实时率及 CPU 推理帧率。

最终展示应能说明“去了哪个房间、搜索了哪些视角、找到哪些编号、为什么是这个数量”，并保存 JSON、编号地图和演示记录。场景优化的验收依据包括识别与导航表现，以及展示效果。
